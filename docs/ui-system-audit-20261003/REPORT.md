# DuckDB Studio 全系统 UI、功能与交互审查

日期：2026-10-03（本地工作区）。使用 Product Design 的 audit 技能；保留现有 Monokai 气质，以当前源码和本次实际浏览器截图为依据。

## 结论与覆盖边界

已扫描 339 个生产 TSX 组件文件与全局样式/主题/工作区状态边界，实际浏览 17 个主入口，并检查分析中心六个子模式、本体三个视图及代表性弹窗。修复聚焦共用主题、排版作用域、叠层键盘行为、SQL 工作区状态、反馈和响应式容器。没有重建正常页面，也没有生成或导入 Mock 数据。

这不是“339 个组件全部人工运行通过”的声明。清单中的颜色、TODO、dialog 数量是定位信号，不能单独认定缺陷；稳定实现和用于图表/实体分类的数据颜色没有机械清除。已有大量未提交改动被保留，Git 相对 HEAD 的总 diff 不能当作本次修改范围。

## 可访问性与仍未验证范围

本次检查了共用弹窗焦点、键盘 Tab/Escape、图谱 Alt+S、明显标签/底色对比、禁用状态和窄窗口可达性。没有进行完整 WCAG 色差测量、屏幕阅读器、跨浏览器、所有设备以及每个组件的排列组合测试，不能据截图宣称无障碍合规。

浏览器使用现存 OPFS 数据；没有跑教程 DDL/DML、批量删除、清空图谱、导入假数据或改写数据库表。外部模型/API、远程插件/湖仓、外部文件权限、每一种导出文件内容与超大数据量性能未逐一执行，仍需要相应实际环境验证。CSV/JSON 保持导出已加载结果，Parquet 保持重新查询导出全部结果，界面现在明确这一区别。
