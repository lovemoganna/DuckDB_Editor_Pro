# 首页组件修复与回归记录

## 执行需求

用同一套真实数据验证首页。先复现问题，再定位根因，按底层模块、基础组件、组合组件和首页顺序修复。每次只改已确认的缺陷，完成局部测试后执行整体回归。保留 DuckDB、Chart.js、现有 IDE 风格、有效功能和用户配置。统一加载、计算、渲染、筛选、尺寸、全屏和错误处理。记录修改、证据和遗留问题。不得用页面能显示代替功能通过，不得扩大数据集范围或无依据重写首页。单数据集验收完成后，才能进行有限兼容性验证。

## 复现与遗留

在项目目录运行 `./scripts/test-home-baseline.ps1 -Repeat 2 -Build`。可用 `-LogDirectory` 指定日志目录。脚本校验固定文件，执行类型检查、重复核心回归和构建，任一步真实退出失败即停止。

启动时原 5173 服务来自另一个项目；已在 127.0.0.1 恢复本项目开发服务，未停止其他项目。现有会话仍可能提示 brd_validation_1008 的 SQL 副本缺失；没有删除或伪造该附件，属于既有状态问题。原构建依赖的 eval 和分包警告保留。

本轮交付确认缺陷的修复与可复用回归，不宣称完成所有组件级验收。尚未开展其他数据集兼容性测试。待验证项目与已通过项目分开记录。
