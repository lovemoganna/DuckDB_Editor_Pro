# Step 4 执行合同：交付与验收

版本：1.1.0

## 输入

只读取：

- G1—G3 PASS 的三个阶段产物；
- Run_Manifest.md 中的 delivery_contract。

任一上游门禁未通过时停止，不得在交付物中修补模型。

## 输出

生成两个文件：

1. 最终交付物，例如 Ontology_Tutorial.md；
2. Step_4_Quality_Report.md。

最终交付物只包含读者需要的内容。稳定 ID、门禁记录和内部审计只进入质量报告。

## 最终交付结构

内容顺序必须遵循：

1. 问题与最终成果；
2. 源实例事实；
3. 从实例到本体的抽象；
4. 盲测案例实例化；
5. 预期答案与模型答案比较；
6. 复用、扩展和范围判断；
7. 可直接执行的模板。

具体标题、长度和风格服从 delivery_contract。

## 质量报告

Step_4_Quality_Report.md 必须包含：

- 闭环完整性；
- 从交付章节到 CQ、类型、关系和约束 ID 的追溯矩阵；
- 复用回归证据；
- 事实边界检查；
- 格式与可执行性检查；
- G4 决定。

## G4 门禁

只有同时满足以下条件才能标记 PASS：

- 交付物符合读者、场景、形式和长度合同；
- 模型层与实例层清楚分开；
- 至少一次复用不是口头声明，而是冻结模型后的实例映射与 CQ 盲测；
- 全部 CQ 比较结果均为 MATCH；
- 所有重要结论可追溯；
- 推断和未知没有被写成事实；
- 交付物不包含内部审计噪音；
- 自动验证脚本可以通过。

模型失真时标记 RETURN 并退回 Step 2；纯表达或结构问题留在 Step 4 修正。

## 禁止

- 不新增上游不存在的模型事实；
- 不把质量报告混入最终交付物；
- 不重复完整中间产物；
- 不在通过后继续无目标润色。
