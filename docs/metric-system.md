# 专业数据分析指标系统

本轮在现有指标库、数据库隔离、验证、图表与版本管理基础上补全建模和知识体系。口径依据于 2026-10-10 检索核对，指标结果由当前来源实际计算；不预置业务结果、目标值或示例数据。

## 结构与覆盖

MECE 适用于同一分类轴，不能把“营收、比率、同比、护栏”放在一组互斥类别中。本系统分别组织以下轴，一个指标可以同时拥有各轴属性。

| 分类轴 | 分类及职责 | 系统入口 |
|---|---|---|
| 计算原语 | 计数、去重、求和；均值、极值、中位数、分位数；标准差、方差；加权均值、聚合比率 | 计算模板 / 字段与聚合 |
| 分析方法 | 原始聚合；累计、滚动、环比、同比；队列留存、有序漏斗、快照、构成占比 | 分析变换 / 方法向导 |
| 业务领域 | 交易与变现、客户与使用、增长与渠道、履约与服务、存量与资源、风险与质量 | 24 项业务口径索引 |
| 决策用途 | 结果、驱动、护栏、诊断 | 口径契约 |
| 生命周期 | 草稿、业务复核、废弃；执行验证另行记录 | 口径契约 / 卡片 / 版本 |

业务领域用于导航，可按组织业务调整；它不证明某个字段代表营收或某条记录代表客户。专业方法按“定义→测量→组合→时间→路径→诊断→验证→治理”八个环节组织。归因、实验和预测的知识覆盖不代表系统已经实现自动模型。

## 可执行能力

| 能力 | 计算规则 | 边界 |
|---|---|---|
| COUNT / COUNT DISTINCT | 行数、字段非空数、非空主体去重 | 一行一主体时行数才等于主体数；去重不可跨期相加 |
| SUM / AVG / MIN / MAX | 按总体、分组和时间粒度聚合 | 空集合 SUM / AVG 通常 NULL；不自动当零 |
| MEDIAN / QUANTILE | 中位数、连续插值分位数，分位点 0–1 | 不对各组分位数再平均；无近似算法误差声明问题 |
| STDDEV / VAR | 分开支持 SAMP 与 POP | 样本分母 n−1，总体分母 n；方差单位平方 |
| WEIGHTED_AVG | 有效数值×权重之和 / 对应有效权重之和 | 成对非空；权重和零返回 NULL；负权重需业务审核 |
| RATIO | 分子和分母独立 COUNT / COUNT DISTINCT / SUM + FILTER，再相除 | 共同 WHERE 与分组一致；倍率 1 或 100；零分母 NULL |
| 累计 | 按时间排序、维度分区的累计求和 | 仅可加 COUNT / SUM；从过滤起点开始 |
| 滚动 | 含当前期的 N 期日历 RANGE | 仅可加 COUNT / SUM；不把 N 行当 N 个日历期 |
| 环比 / 同比 | (本期−基期)/基期×100，严格日历期间匹配 | 缺失 / 零基期 NULL；负基期需解释；周同比不等于 ISO 同周 |
| 第 N 日留存 | 首次入组日期 cohort 内，第 N 个业务日回访的去重主体 / cohort 主体 | 首次来自提供历史；需历史完整；只纳入成熟 cohort；不是滚动留存 |
| 两步有序漏斗 | 每主体首次起点一次机会；完成时间严格晚于起点且≤起点+窗口 | 仅纳入完整观察窗；不支持多次机会归因或任意多步漏斗 |
| 月末快照 | 每主体每月按时间与唯一排序键降序取末条，再汇总 | 不前向结转；未观测主体不计入；同时输出已观测与非空值主体数 |
| 构成占比 | 分组可加量 / 全部分组量×100 | 保留未知分组；零总量 NULL；负金额会产生负占比，需解释 |

口径契约中的可加性描述输入基础度量；累计与滚动结果沿时间不能再相加，增长率结果不可相加，卡片另行提示结果汇总边界。

时间分组支持 hour、day、week、month、quarter、year。时间元数据只是口径登记，不会隐式转换会话时区；时间字段应先在模型或 SQL 中统一到业务时区。缺失期间默认不补零，不自动生成完整日历。

## 建立与审核流程

1. 定义问题与决策用途，确认指标总体、主体、事实粒度及唯一业务键。
2. 在当前数据库创建 / 打开指标包，选择真实来源；跨表先校验连接基数和聚合粒度。
3. 选择计算模板，或用留存 / 漏斗 / 快照 / 占比方法向导绑定真实字段。向导仅生成待核验定义，不直接写入指标包。
4. 配置过滤、维度、时间、倍率及规则。复杂派生、跨表比率、归因和多步路径使用完整只读 SQL。
5. 登记负责人、统计主体、事实粒度、时区、更新频率 / 延迟、排除与空值规则、用途及可加性。
6. “验证计算”实际执行；检查预览结果、独立对账与边界样本，再保存。技术验证与“已业务复核”分别记录，未审核项保持草稿。
7. 生成图表并建立分析引用。变更定义后重新执行，登记口径版本；治理字段纳入版本历史。
8. 导出可保留计算结构与口径契约；导入后保留来源定义，但清除环境验证状态并回到草稿，在当前数据库重新确认。

## 必须复核的口径

| 风险 | 核验方式 |
|---|---|
| JOIN 放大 | 比较连接前后行数、主体去重数、金额守恒；先在同事实粒度预聚合 |
| 错误总体 | 确认分子属于分母资格总体、共同时间窗、退款 / 取消 / 机器人等排除规则 |
| 平均比率 | 保存或重算可加分子分母后相除，不能平均分组百分比 |
| 未成熟观察 | 留存与转化明确观察截止，排除尚未达到目标日 / 完整窗口的主体 |
| 时间边界 | 使用 [开始, 结束)；核对跨月、跨年、缺失期、时区与迟到数据 |
| 单位与币种 | 汇率、税费与确认日期一致；0–1 比例与 0–100 百分数不得混用 |
| 转换失败 | TRY_CAST 失败率另报；不要把 NULL 自动替换成零以掩盖质量问题 |
| 统计推断 | 样本 / 总体分开；相关不代表因果；实验的随机化、功效、多重检验独立设计 |

业务索引包含成交金额、净收入、客单价、毛利率、活跃主体、新客、渗透率、频次、CAC、ROAS、CTR、渠道占比、准时履约、P95 时长、一次解决、单位成本、期末余额、利用率、周转率、账龄、不良率、损失率、缺失率、重复率。索引给出资格与建模要求，不能凭字段名自动认定业务语义。LTV、流失阈值、归因和实验目标依赖业务模型与观察窗口，应另行明确后用 SQL 或专业分析工具计算。

## 定义依据

- [DuckDB aggregate functions](https://duckdb.org/docs/stable/sql/functions/aggregates)：聚合、NULL、分位数与统计函数。
- [DuckDB FILTER](https://duckdb.org/docs/stable/sql/query_syntax/filter)：同一总体内条件聚合。
- [DuckDB window functions](https://duckdb.org/docs/stable/sql/functions/window_functions)：窗口分区及 ROWS / RANGE 的区别。
- [Kimball 可加、半可加与不可加事实](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/additive-semi-additive-non-additive-fact/)：快照与比率重汇总原则。
- [dbt conversion metrics](https://docs.getdbt.com/docs/build/conversion)：转化必须明确实体、事件和时间窗口。本系统两步向导采用“每主体首次起点”的明确约定，并不复制 dbt 的最近机会归因。

以上资料用于技术与方法核对，业务索引中的具体资格定义仍须责任人确认。系统不提供自动因果推断、预测、任意归因、权限审批流或调度告警。
