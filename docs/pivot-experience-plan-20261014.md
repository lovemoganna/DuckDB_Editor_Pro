# 透视表体验改进实施计划

日期：2026-10-14

状态：阶段一至三已实施，完成针对性回归、生产构建和真实浏览器验证。结果与截图见 [验收记录](pivot-experience-20261014/README.md)。两表关联增强保持为后续阶段。

## 目标与边界

用户能从正在查看的数据开始透视，通过明细解释汇总，保存后加入首页，并从首页恢复原有编辑配置。整个过程保持数据来源、筛选范围和计算口径一致。

- 完整编辑器位于「分析洞察 → 透视表」，现有「透视聚合」改名。
- 首页展示保存后的结果，支持刷新、联动、全屏、返回编辑。
- 数据表与 SQL 查询结果提供快捷入口，进入同一个编辑器。
- 保留现有全局导航、其他分析工具和本体切片能力。
- 使用真实数据和现有分析执行、渲染、存储机制，不增加演示数据或第二套聚合逻辑。
- 第一轮不增加独立两表关联模块、复杂本体建模流程、AI 指标自动生成、撤销历史系统或新图表类型。

## 关键用户路径

### 从数据表开始

打开表并应用筛选 → 点击「透视分析」 → 看见当前来源与继承条件 → 调整行、列、值、筛选 → 点击汇总查看明细 → 保存分析 → 可选加入首页。

来源条件在透视页可见；用户明确更换来源时才切换数据范围。来源条件与透视页追加条件分别显示，避免重复应用和误以为已清除上游条件。

### 从 SQL 结果开始

成功执行只读查询 → 点击结果区「透视分析」 → 对该次已执行查询的完整结果继续聚合。

修改但未执行的 SQL 不影响入口来源；查询自身的 LIMIT 属于来源范围，需要提示。错误结果、执行计划、缺失来源元数据的结果不可作为透视来源；提示重新执行，不静默回退到整张表。

### 从首页继续编辑

保存透视分析 → 加入首页 → 首页显示结果 → 点击「编辑透视表」 → 读取同一保存对象的最新定义 → 恢复配置 → 修改并保存 → 原首页卡片随之刷新。

进入编辑时恢复分析自身的条件；首页临时联动条件不自动覆盖保存定义。若提供「按当前筛选继续分析」，使用独立、明确的动作。

## 页面与交互规格

### 编辑器

- 顶部：来源名称、数据范围摘要、分析名称、保存、加入首页。
- 桌面宽屏：左侧配置约 280–340px，右侧结果占余下空间；具体断点按应用侧栏展开后的可用宽度验证。
- 左侧：明确的「行」「列」「值」「筛选」分区，支持点击选择与移除；拖拽可以后续补充，不作为唯一操作方式。
- 右侧：默认透视表，允许切换图表；显示聚合口径、结果限制、计算状态。
- 高级操作：SQL、复杂计算、显示格式按需展开；不占据常驻主操作区域。
- 窄屏：配置可折叠展开，提供明显的「配置透视表」按钮；结果保持可读，横向滚动限制在表格内部。
- 初期支持一个行维度、一个可选列维度；现有多度量能力保留，单元格和总计必须明确对应度量。暂不扩展多层列分组。
- 行列互换使用明确按钮，不能通过改变数组顺序而丢失聚合、日期粒度或筛选设置。

### 默认配置

- 优先选择可靠类别字段；日期可按月分组；标识字段不作为优先分组。
- 不可靠的数值口径默认使用记录数。已明确为可加总度量的字段可沿用字段目录聚合建议。
- 标识字段不默认求和；金额、比例、库存等不同语义不能仅凭数值类型统一求和。
- 保留现有单位隔离规则；没有选定必要计量资产时不执行混合汇总。
- 高基数判断若需要额外查询，采用限额统计或已有体检结果，不阻塞整个编辑器。

### 明细查看

- 点击数据单元格或明确的明细动作，在有标题的侧边抽屉中显示来源记录。
- 条件包含原始来源条件、透视筛选，以及当前行与列的分组值；月份分组采用准确的时间区间，空值采用空值条件。
- 明细分页读取，不取全量到浏览器；显示页码与范围，不伪造总行数。
- 抽屉内展示生效条件；关闭后保持透视配置、滚动位置和结果。
- 支持键盘进入、Escape 关闭、焦点返回触发单元格；计算错误在抽屉中可重试。
- 来源是聚合 SQL 时，明细指该查询输出中的记录，不能承诺自动追溯到查询之前的原始业务记录。

### 保存与状态

- 一次操作保存分析，成功反馈包含「加入首页」「继续编辑」；不强制跳到另一个页面再保存。
- 首次保存可命名；更新沿用原分析 ID；另存为使用独立动作。
- 保存定义包含来源、库与 Schema、行列配置、度量及聚合、日期粒度、筛选、排序、结果限制、视图类型、单位选择和标题。
- SQL 与图表配置是执行结果，不替代可编辑定义；保存时必须与成功计算的同一版本匹配。
- 配置修改后立即标为待计算，短暂合并连续输入；新请求优先，旧请求不能覆盖结果。
- 待计算、计算中、失败时禁用保存结果和导出，避免保存旧结果搭配新配置。
- 失败保留配置并允许重试；切换来源后不展示上一来源的结果。
- 未保存配置在同一会话切换子页后可恢复；按来源隔离草稿。跨来源携带配置时需校验字段，不能自动映射同名字段。
- 离开有未保存修改的编辑状态时提供保留草稿/放弃的明确路径，不在每次切换图表时弹确认。

## 实施顺序与交付物

### 阶段一：来源与配置闭环

1. 记录相关文件副本和类型、测试基线。
2. 定义带版本的透视保存结构，扩展现有分析记录，旧记录保持可读。
3. 统一解析表、已执行 SQL、带筛选数据集；扩展现有分析引擎的来源承接方式，不将 SQL 字符串当作表名引用。
4. 完成直接保存、更新、另存为和恢复编辑；首页已有引用沿用分析 ID。
5. 数据表与 SQL 结果接入同一个透视打开动作。

完成条件：从带筛选的表和成功查询进入，保存、刷新、重新打开后，配置与数据范围一致；被删除或跨库、跨 Schema 的来源明确报错。

### 阶段二：透视编辑与明细体验

1. 「透视聚合」改名「透视表」；保持内部标识与旧导航存储兼容。
2. 明确行列值筛选四区，调整为配置与结果分栏，窄屏配置可折叠。
3. 接入现有交叉表渲染，完成行列互换、图表切换与聚合口径提示。
4. 实现准确的明细下钻、日期与空值处理、分页和焦点管理。
5. 完成请求竞态、错误、空态、待计算与脏配置处理。

完成条件：用户能完成“按地区 × 月份汇总 → 找到异常单元格 → 查看对应明细 → 返回继续调整”，无数据范围丢失、错误总计或配置重置。

### 阶段三：首页闭环与真实交互验证

1. 保存后加入首页，首页保留紧凑结果、刷新、联动和全屏能力。
2. 透视卡片提供「编辑透视表」，恢复最新保存定义；普通历史记录不被误路由。
3. 编辑保存后原卡片重新计算；来源失效显示可操作错误，不能展示旧结果冒充新数据。
4. 运行有针对性的单元与集成测试、类型检查、生产构建，记录新问题与基线问题。
5. 浏览器验证完整流程和两种宽度、键盘路径，保存真实验证证据。

完成条件：数据 → 透视 → 明细 → 保存 → 首页 → 编辑 → 首页更新全链路通过。

### 后续阶段：两表关联增强

单表与查询闭环完成后，再复用本体切片关系选择能力：候选关联字段 → 唯一性/空值/匹配率/基数检查 → 确认关联结果 → 继续透视。多对多和一对多必须展示重复累计风险并提供适合该口径的处理，不自动认定同名字段就是主键。

## 验收清单

| 场景 | 预期 |
| --- | --- |
| 表已有筛选，从表进入 | 透视与明细均继承条件，清除追加条件不意外清除来源条件 |
| SQL 查询结果分页 | 透视基于已执行查询，独立于当前页；显式 LIMIT 提示属于来源范围 |
| 编辑器文本已改但未执行 | 仍使用上次成功执行结果的 SQL |
| 一张表只有数字编号 | 初始不会将编号求和 |
| 不同单位混在同一表 | 必要的单位选择生效，结果不能混合合计 |
| 行列互换、切图、查看明细 | 聚合、筛选、日期粒度和单位保持不变 |
| 某行某月的单元格 | 明细包含行列两边条件，空值和日期边界正确 |
| 平均值与去重计数 | 小计、总计按正确口径计算，不能直接加总显示单元格 |
| Top N 或结果限制 | 明确当前展示范围，总计不得误标为完整总体 |
| 快速连续修改配置 | 最新请求结果生效；计算未完成不能保存错配版本 |
| 保存后刷新与再次打开 | 所有编辑配置恢复，数据重新计算 |
| 首页修改后返回编辑 | 保存定义不被首页临时联动覆盖 |
| 更新原分析 | 原首页引用继续有效，不新增重复分析或卡片 |
| 删除来源、字段或分析 | 明确显示错误，不回退到其他表或历史结果 |
| 相同表名分布于不同 Schema | 来源身份准确，拒绝作用域漂移 |
| 历史记录只有 SQL | 可继续查看；不能假装可无损还原透视配置 |
| 1366px 与 768px 窗口，侧栏展开 | 主要动作可见、结果有空间、页面无整体横向溢出 |
| 键盘完成配置、明细开关、保存 | 标签可读、焦点可见，抽屉关闭返回触发点 |

## 验证方法与证据

- 编译与持久化测试覆盖来源隔离、查询来源、旧记录兼容、配置恢复和更新身份。
- 组件测试覆盖快捷入口、保存状态、行列互换、明细行列条件、请求竞态和键盘行为。
- 聚合测试用可手工核对的数据验证求和、平均、记录数、去重计数以及总计；测试夹具只用于测试，不写入产品默认数据。
- 应用中使用实际工作区数据验证筛选继承与首页回流，不改变用户数据。
- 记录相关测试、类型检查、构建和浏览器验证结果；已有失败单列，不能以部分通过宣称整个项目通过。
- 体验验收关注用户是否能独立完成上述三条路径、是否重复选源、是否误解汇总和是否丢失配置。缺少真实用户观察时，报告为内部交互验证，不声称已经完成用户可用性测试。
