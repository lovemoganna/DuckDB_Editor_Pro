## 依赖与职责

入口实际挂载 Dashboard，经 useDashboardWorkflow 获取元数据和当前看板，进入 DataIdeMissionControl，再由 HomeBoardCanvas 组合首页。首页没有另造一个分析引擎。

| 层 | 输入、输出与职责 | 状态边界 |
|---|---|---|
| datasets / queryCompiler | 真实元数据、数据集定义、显式筛选映射 → 参数化 SQL、来源 ID、适用范围提示 | 不保存 UI 布局；无法安全筛选时明确失败 |
| workbench/runtime | 查询定义、上下文、联动、修订号 → 行数据、总数、字段类型、执行时间与提示 | 执行缓存、失效通知；真实查询结果 |
| Chart.js 适配器 / ChartRenderer | 行数据和 ChartSpec → 图表、指标、表格 | 共享格式、尺寸、图例；本轮增加可选受控图例接口 |
| useContainerSize / chartSpace / tableSpace | 实测容器及内容 → 绘图区和滚动预算 | 自动测量不得保存布局 |
| DashboardWidget | 保存的查询 ID → 查询结果、卡片、菜单、全屏 | 请求代次、最后成功结果、错误、卡片与全屏共享图例 |
| DashboardGrid | 保存坐标、组件类型、实测宽度 → 浏览临时排版或 12 列编辑画布 | 浏览缩放不保存；主动调整才通知保存 |
| DatasetPreview | 同一数据集、上下文、联动、修订号 → 明细 | 使用相同查询编译；分页大小与组件不同是明确输出差异 |
| HomeBoardCanvas | 看板、owner、加载状态、修订号 → 控制区、网格、明细 | 数据集加载单一入口及代次保护；公共刷新信号；保存由 dbService 串行更新 |
| DataIdeMissionControl | 元数据、加载状态、已有看板 → 首页状态 | 初次加载与已有数据刷新分开，不卸载已有工作区 |

## 缺陷、根因与最小修复

| 编号 | 复现与根因 | 修改 | 回归证据 |
|---|---|---|---|
| C1 | 有数据后刷新元数据或看板，两层 loading 分支卸载子组件，局部选择丢失 | DataIdeMissionControl 不将刷新等同于无数据；HomeBoardCanvas 仅初次无看板时阻断渲染，保留 aria-busy | lifecycle-before 两项失败；HomeLifecycle 两项通过；浏览器重复刷新保留明细和图例选择 |

| C3 | 读取失败后重试，更新请求已成功，旧请求失败又写入错误；两套数据集加载路径保护不一致 | HomeBoardCanvas 合并读取入口，owner、修订更新及卸载均使旧代次失效 | datasets-before 失败；新成功后旧失败测试通过 |

| C5 | 卡片关闭 net，进入全屏后 net 重新显示；两个渲染实例独立保存图例状态 | ChartRenderer 支持可选受控图例；DashboardWidget 按查询与图表 ID 共享可见性，不保存为布局修改 | 共享渲染器及卡片/全屏测试；浏览器 false/false、true/true 双向验证，07 截图 |

## 重复执行

在项目目录运行 `./scripts/test-home-baseline.ps1 -Repeat 2 -Build`。脚本先校验固定文件哈希及 DuckDB CLI，再执行类型检查、两轮核心测试和构建。失败立即停止，不跳过真实数据库测试。数据库文件不匹配时必须先审查基线，不自动换数据。真实引擎集成测试只替换浏览器传输与保存定义边界，SQL、参数、运行时、结果和数据库执行均真实。组件独立测试的替身只验证生命周期、请求顺序和交互信号，不作为业务数据正确性的证据。

最终核心回归两轮均为 14 个文件、65 项通过。类型检查通过，构建通过（43.50 秒）。详见 core-round-1.log、core-round-2.log、typecheck.log 和 build.log。中途发现新缺陷时停止旧一轮，完成局部修复后重跑；等待线程模式轮次期间也停止过执行，core-interrupted.log 和其他未完成轮次不算通过。最终脚本使用独立进程、单工作进程顺序执行，不修改项目全局测试设置。构建已有 DuckDB eval 与分包大小警告分别记录，不作为本轮功能回归。

## 验证边界与遗留

重载期间页面由 11 项变为 10 项，并曾显示编辑状态。只读数据库记录也显示 10 项；用户明确回答「我调整过页面」。该差异不列为组件缺陷，不自动补回完成率卡片。业务数据没有更换。随后以用户最新保存的 10 项、浏览模式继续核验重载；记录在 reload-regression.json。原 11 项的 SQL 完成率 86% 仍由真实引擎测试覆盖，但不能再把当前页面缺少该卡片判为失败。

本轮核心测试、真实引擎和记录的浏览器操作完成后，仍不能宣称整个项目或全部长期运行场景通过。未执行长时间压力测试、浏览器缩放全矩阵、其他浏览器，以及真实用户保存操作的完整增删移动恢复流程。布局保存边界由自动化测试覆盖；本轮没有为浏览器验收改动用户保存坐标。未配置的下钻不临时启用，不增加数据来制造分页。

现有会话曾提示保存的 SQL 数据库 brd_validation_1008 副本缺失。这是既有附件状态问题，与本轮固定四表不同，未重新导入或删除用户保存的定义。仍需在对应附件管理任务中处理，不能标为正常。构建警告保留。其他数据集兼容性未开展，按要求与组件缺陷分开；不以增加数据集掩盖或扩大本轮结论。
