# 仪表盘 BRD 实施与验证记录

本次已修改当前项目。完整验收尚未全部通过。本文区分代码实现、实际验证与待验证项，不将未执行的检查记为通过。

## 实现关系与基线

“分析首页”与全局“仪表盘”使用同一工作台：`App` → `Dashboard` → `DataIdeMissionControl` → `HomeBoardCanvas` → `DashboardGrid`。视图由当前数据库的 `active-home-view` 与仪表盘存储恢复。SQL 结果另走 `ChartDashboard`，通过共享空间规则与其他入口对齐。没有根据名称推断两套独立页面。

任务开始时工作区已有大量未提交修改。本次保留这些修改，没有重置工作区或批量迁移用户布局。所选文件的开始版本位于 [baseline](baseline/)，开始时类型检查通过，见 [基线日志](typecheck-before.log)。

## 问题与修改对应关系

| 问题 | 本次修改 |
| --- | --- |
| 首页大型技术模块与结果争夺空间 | 移除首页的数据来源与检查大模块、资产栏和重复说明，保留数据管理、Schema 与检查入口。SQL 口径仍可在组件与查询详情查看。 |
| 字段类型被直接解释成业务价值 | 停止自动生成任意数值 SUM 和根据字段名称自动创建业务指标包。自动候选仅生成有真实结果的描述性分类统计、有效日期按月记录分布；记录数作为数据规模，不填入固定首页 KPI。保留已有用户定义。 |
| 旧定义被误当成数据存在 | 空库不因保存了组件定义而展示失效占位。定义仍保存在原存储中。 |
| 不同单位参与同一合计或比较 | 新建组件中，已识别的单位维度参与聚合分组，并采用明细表展示。没有换算过程，不合并金额单位。 |
| 元数据范围与统计口径不一致 | 首页行数查询限定当前数据库和 Schema。统计未获取时显示未知，不使用估计字节数或失败后的零。顶部注明行数未应用筛选。 |
| 没有主键被扣分，查询失败被当成正常 | 数据体检移除无依据的健康评分和固定大小估算。完备率只显示查询结果，给出非空单元格比例口径；失败与空数据均不填充 100%。可空字段的空值作为观察。 |
| 质量检查没有可追溯证据 | 增加真实非空、唯一及外键约束检查，以及用户选择的字段唯一性规则。保存全量失败数量、来源 SQL 和前 20 行证据。区分未检查、通过、发现规则失败、检查失败和数据不可用。 |
| 首页检查入口打开了关联分析 | 显式请求数据体检模式。首页只显示已执行范围的最近检查状态，问题入口定位到对应数据集。数据或 Schema 变化使会话检查证据失效。 |
| 图表、指标和小表被同样分配空间 | `dashboardLayout` 按内容分配最低空间。新指标组件采用紧凑默认尺寸，普通图表保持桌面初始最低空间。旧布局不迁移。 |
| 跨断点替换网格，关闭全屏等交互 | 浏览模式使用同一组组件改变 CSS 排版。宽度不足时临时少列；可用时仍按保存坐标呈现。编辑模式继续使用 12 列网格及可滚动画布。 |
| 窗口变化可能触发布局保存 | 浏览排版和测量不保存。仅用户拖动、调整尺寸或编辑保存提交布局。 |
| 配置栏撑高图表预览 | 图表编辑预览从约 1100px 绘图区改为共享内容尺寸；普通图预览绘图区实测 368px。 |
| 窄屏侧面图例继续挤压绘图区 | 共享渲染器与 SQL 路径根据实际容器宽度安排图例；窄容器采用上下布局和独立滚动。 |
| 图例切换与尺寸变化状态不一致 | 图例显隐与 Chart.js 状态同步，尺寸变化后保留用户主动隐藏的系列或分类。 |

新增主要文件：`utils/dashboardLayout.ts`、`services/dataInspection.ts`、`components/AnalysisHub/DataQualityChecks.tsx`、`hooks/store/useDataInspection.ts`。同时修改首页工作流、候选分析生成、共享图表渲染器、SQL 图表、图表编辑器、分析中心和可视化卡片。继续使用 DuckDB、Chart.js、现有存储类型与 IDE 风格。没有修改知识图谱或数据流拓扑。

### 功能与口径

已验证：实际创建记录规模卡与长分类图；布局拖动；右下角调整尺寸；完成编辑；离开页面后重新打开；继续编辑恢复同一位置和尺寸。[重新打开的布局](saved-layout-reopened.json)显示记录卡由 x=0 移到 x=3，宽度由 3 列调到 4 列。浏览跨断点不重新挂载组件的行为另由自动化验证。

已验证：全局 USD 条件进入聚合前的查询，记录卡由 120 变为 60，分类结果由 60 组变为 30 组，见 [筛选结果](filtered-after.png)。未筛选分类查询在 SQL 工作台返回 60 行、每组 2 条；导出得到 [完整 CSV](classification-export.csv)，共 60 条结果，没有以缩减查询结果解决空间问题。

已验证：环图完整图例保留 60 项及每项数值、占比；隐藏第一项后从 1280 切至 390px，按钮仍为未选中。[桌面环图](doughnut-preview.png)、[窄屏环图](doughnut-preview-390.png)。全屏跨五种宽度继续保持打开。页面隐藏后重新显示仍可查询并展示。

已验证：没有主键的隔离表执行检查后，显示“已执行，未发现规则失败”，不扣分，见 [无主键检查](inspection-no-key-after.png)。显式选择 category 唯一性规则返回 60 组重复对象，见 [检查页](inspection-after.png)。空值、主键、唯一和外键查询以及失败状态另有真实原生 DuckDB 测试。

已验证：检查结果返回首页后显示“最近检查：1 / 1 个数据集 · 发现规则失败”。点击“处理检查问题”进入对应数据表的体检页，恢复同一检查时间、category 规则和 60 项结果，没有重新执行检查。见 [重新打开的检查](inspection-restored-after.png)。
