# 可自由构建的分析工作台：实现规划

状态：已实施首个可用版本，最终验收记录见 analysis-workbench-delivery.md。以下保留原批准规划；实际实现与后续增强在交付记录中逐项区分。基于 2026-10-04 当前代码。目标平台为现有本地 DuckDB Studio，保留 Monokai 风格、真实数据、原指标定义与现有拖拽布局。

## 目标与产品闭环

用户选择或组合数据集 → 创建/选择指标和分析 → 添加组件 → 为每个组件配置展示与筛选 → 拖拽编排 → 统一筛选与交叉联动 → 数据变更正确重算 → 保存、重开并继续编辑。

完成标准是这个闭环可以用真实数据验证，不以按钮数量、组件数量或页面标题作为完成依据。

首个里程碑在一个数据库内完成全闭环；最终阶段支持多个已附加数据库的数据集同时放置，以及具备明确关联规则的组合分析。多个互不兼容的数据集可以同时展示，但不能强行共用不存在的字段和指标口径。

## 核心数据契约

以下名称为拟新增或扩展的契约，不代表当前已有全部实现。

1. **DatasetDefinition**：稳定 ID、来源 catalog/schema/table 或查询、字段稳定 ID/类型/含义、单位、时间字段、关联定义、定义版本。字段显示名不能承担唯一身份。
2. **AnalysisDefinition**：原始指标/图表/分析身份、datasetId、维度、度量、聚合方式、支持的筛选、单位及定义版本。继续引用来源定义，不复制出第二套指标。
3. **DashboardItem 实例设置**：唯一实例 ID、来源对象、局部筛选、展示覆盖、参数绑定、参与的联动组及布局。同一指标重复放置后，各实例可以独立配置。
4. **DashboardContext**：看板级筛选、时间范围、参数、字段映射、联动组和版本。不要用一个全局 currentTable 表达所有组件的数据来源。
5. **QueryResult**：字段、结果、查询指纹、来源版本、执行时间、完整性/截断说明、状态与错误。区分完整聚合结果与受限明细预览。
6. **RefreshPolicy**：手动、应用内数据变更、可选定时；说明外部更新检测方式。单个组件记录最后成功结果与更新时间。

保存的看板默认筛选与临时交互选择分开；组件局部筛选、全局筛选和图表选择具有显式优先级。显示覆盖不修改来源定义，修改来源定义必须使用单独入口。

## 阶段 0：固定现状与回归基线

目的：让后续升级能够证明没有破坏旧看板。

- 记录旧资金视图和用户视图的查询定义、组件身份、布局与口径。
- 解决全量测试挂起的定位问题，区分测试环境警告与实际用例失败；先保证相关回归可稳定完成，不降低业务断言。
- 检查 Dashboard/DashboardItem 等重复类型声明，只在引入新契约时收敛同一数据结构。
- 用独立测试数据库构建金额、日期、地区、客户、多币种、多表关联案例；真实 DuckDB 执行，用户数据库不被修改。

验收：旧看板重开、来源跳转、SQL 结果、拖拽保存保持正确；已知挂起有可复现范围和处理结论。

## 阶段 1：同库数据集模型与组件实例独立设置

交付：内容库可按数据集选择对象，同一指标可以分别设置两个组件。

- 引入 DatasetDefinition，接入现有自动发现与用户 SQL 数据集；先支持同一 catalog 内的多表/多 Schema。
- 组件显式绑定 datasetId；引用来源对象和定义版本。
- 扩展 DashboardItem 实例设置：标题、图表展示、局部筛选、格式、计量单位。
- 来源定义与实例覆盖分离；同一个来源在两个组件中的配置互不污染。
- 使用现有抽屉/表单实现实例编辑，不另造首页专用控件系统。
- 对旧看板按当前绑定来源迁移；无法明确解析的来源显示待绑定，不偷偷改 SQL。

验收：同一销售额指标放两次，分别分析地区 A/B；修改 A 的样式和局部筛选不改变 B 或指标中心；保存重开配置不丢失。

## 阶段 2：统一上下文与筛选驱动的真实重算

交付：一个时间/地区筛选同时驱动 KPI、趋势、分布和明细。

- 引入共享看板运行上下文，集中管理筛选、时间范围和参数。
- 共享查询模块负责定义解析、字段绑定、只读校验和查询生成；组件仅提交执行请求并呈现结果。
- 标准指标从结构化数据集/维度/度量生成查询，WHERE 位于聚合之前。
- 自定义 SQL 提供类型化参数或明确的数据集查询契约；不能假设任意聚合 SQL 在外面包一层 WHERE 就等价。
- 未支持的 SQL/字段绑定显式显示不参与筛选及原因；禁止悄悄忽略仍显示“已联动”。
- 参数采用 DuckDB 支持的绑定方式；标识符只能来自已验证元数据，避免字符串拼接任意条件。
- 完整聚合在 DuckDB 执行；明细使用分页和总数。现有 1000 行预览上限不能被当成完整分析数据。

验收：三个组件在同一时间/地区筛选下与独立 SQL 验算一致；NULL、空结果、时区边界、跨币种和长筛选输入有明确结果；不兼容组件明确说明原因。

## 阶段 3：交叉联动、下钻与刷新调度

交付：点击图表能正确重算相关组件，并且数据改变后结果更新且不会互相覆盖。

- 联动通过字段稳定 ID、语义映射和联动组传播，支持清除、返回及多条件组合。
- 交叉筛选重新执行受影响查询；下钻打开带上下文的明细，不只是过滤前 1000 行结果。
- 共享执行模块管理依赖、并发上限、请求合并、缓存与过期结果隔离。
- 缓存键包含来源/定义版本、实例设置和有效上下文。
- 当前 DuckDB 适配器不支持可靠取消时，至少丢弃旧请求结果；不能虚假显示“已停止”。
- 应用内数据变化产生明确的业务数据修订事件；保存看板元数据不应再次触发业务数据重算循环。
- 提供刷新策略、更新时间、部分失败、重试及最后成功结果的状态说明。
- 仅承诺被检测的变化；外部文件/远程源使用显式刷新适配或定时策略，不承诺自动实时检测任意外部更新。

验收：快速连续切换筛选时最终结果属于最后选择；某组件失败不清空其他组件；更新测试表后一组相关组件重算；保存布局不会引发循环刷新。

## 阶段 4：多数据集组合与跨库运行

交付：同一看板可以展示不同已附加数据库的数据；需要关联时可以创建组合数据集。

- 看板拥有者与组件数据来源分开，组件按自身来源运行，切换当前数据库不改变其身份。
- 来源 catalog/schema 必须显式限定，校验附加状态、字段兼容性和访问范围后才能执行。
- 从已声明来源生成执行范围，代替当前“一律禁止跨库”的规则；不能直接移除限制。
- 支持组合数据集中的 JOIN/UNION，展示连接键、关联基数和不同类型合并规则。
- 检测多对多 JOIN 的重复计量风险；明确时间粒度、计量单位和指标聚合规则。
- 原 SQL 编辑器跨库查询保留；自助建模操作逐步接到同一组合数据集定义。
- 数据源缺失或变化时局部失效并提供重新绑定，不自动执行另一个同名表。

验收：订单库与客户库关联后销售额不因一对多而重复；独立数据集同屏展示；公共地区字段可联动，无映射的组件显示不适用；关闭一个来源只影响依赖它的组件。

## 阶段 5：保存、持续编辑与完整产品验收

交付：完整的可持续编辑体验，以及明确的兼容与恢复行为。

- 创建/重命名/复制视图，保存布局、组件实例、默认筛选、数据集绑定与刷新策略。
- 编辑草稿和自动保存失败有明确状态；恢复后不丢失最后一次成功保存。
- 格式版本和升级迁移可测试；来源定义更新与实例覆盖的合并规则明确。
- 首版至少提供实例配置取消/应用；完整多步撤销可作为后续增强，不阻塞数据正确性闭环。
- 统一 Loading/Empty/Error/Success、主题、键盘操作、窄窗口和长标题行为。
- 团队协作、权限管理、云发布及实时多人编辑另立范围，不通过本地保存能力宣称已经具备。

验收：建立自定义看板、保存、关闭重开、修改和再次保存成功；旧看板迁移保持 SQL 与口径；数据源失效可恢复；不同窗口所有信息与操作可访问。

## 交付顺序与检查门槛

执行顺序：0 → 1 → 2 → 3 → 4 → 5。每阶段都有可操作界面、真实 DuckDB 验算、相关回归和最终构建。阶段 1–3 形成首个同库闭环，阶段 4–5 达成完整目标。没有数据正确性证明时，不进入增加展示组件数量的工作。

建议首个实现切片：一个订单数据集 + 地区/时间统一筛选 + 销售额/趋势/明细三个组件 + 独立实例设置 + 保存重开。贯穿来源绑定、查询编译、结果展示与持久化后，再扩展其他数据集和分析类型。

不采用大规模重写。每次替换一个共同根因，移除被替换的旧路径，避免新旧上下文、过滤器和刷新调度长期并存。新增通用模块必须实际服务多个使用点，不预造只有转发功能的抽象层。

现阶段不承诺具体工期；阶段 0 明确测试挂起、SQL 解析/绑定能力与跨库执行成本后再评估。主要技术风险是任意 SQL 的可筛选性、关联后重复计量、上下文切换和异步刷新竞态。
