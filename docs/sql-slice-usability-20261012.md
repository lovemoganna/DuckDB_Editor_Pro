# 数据切片图谱：操作简化与后续规划

> 历史记录：独立弹窗方案已被撤除。当前实现与验收请见 [主图谱接入记录](sql-slice-main-graph-integration-20261012.md)。

日期：2026-10-12。范围：本体图谱的 SQL 切片入口、条件设置、执行反馈和来源追溯。沿用现有组件、配色与图谱引擎，不修改原有本体数据。

## 证据与问题

本轮开始时，实际页面将交易的 `uid` 选为对象标识、将 `users.user_name` 选为关联键，查询因数字与姓名转换失败。截图确认页面同时展示多个技术字段、SQL 和映射 JSON，常规筛选要求用户自行修改 WHERE。

![优化前：标识误选、关联失败与技术输入负担](/C:/Users/luoyu/Desktop/Duckdb_Manager/duckdb-editor/output/playwright/sql-slice-usability/before.png)

按互斥职责划分检查与修复：

| 环节 | 已确认的体验问题 | 本轮实现 |
|---|---|---|
| 对象选择 | 用户需知道主键；重复 uid 容易被当作交易标识 | 对真实数据检查唯一且非空的候选标识，显示检查结果，允许调整；执行前拦截重复和空值 |
| 任务范围 | 简单条件也要写 SQL | 字段、匹配方式、值的表单筛选，多条件 AND，字段真实值建议最多 50 个 |
| 关系设置 | 需手选两端字段，容易误选 | 关联按需展开，目标唯一键经数据验证；存在同名来源字段时预填候选，明确提示确认业务含义 |
| 查询执行 | 生成 SQL 与得到图谱之间缺少业务动作 | 主按钮改为“查看图谱”，筛选变化自动重算；切换对象或关联需重新查看 |
| 结果阅读 | 数字标识与混杂列表难理解，原始 JSON 占据主视图 | 优先用真实 name/title 字段作为标签；对象/关系分开、可搜索；来源、标识、属性可直接阅读 |
| 进阶操作 | 技术配置占据默认路径，筛选与手动输入可能互相覆盖 | SQL 与映射折叠；明确切换手动模式，筛选停用，返回筛选模式的按钮明确标注清除手动查询 |
| 状态和安全 | 改条件后可能误读旧图，异步结果可能晚到 | 保留立即清空旧投影、请求序号、数据库上下文检查、空结果、错误和 1,000 行限制；增加异步标识建议防串表 |

## 现在的操作路径

1. 进入“AI 认知 → 本体图谱 → 数据切片”。
2. 选择真实来源表；系统尝试验证对象标识，不能确认时要求选择，绝不把重复 uid 自动当成订单标识。
3. 按需添加筛选，输入或选择实际值；不添加则查询全表（仍受 1,000 行限制）。
4. 需要关系时展开“关联其他对象”，选择目标表并确认候选关联字段。
5. 点击“查看图谱”。之后修改筛选自动更新，点击节点/关系查看来源。

单表默认路径从手选来源、手选标识、生成 SQL，缩为选表、查看图谱。双表默认路径省去三个手动键字段选择。复杂筛选的操作次数不作统一减少承诺；此次主要降低必须理解 SQL、主键与 JSON 的门槛，尚未进行用户计时实验。

## 实测与验证

真实工作簿使用用户指定的四张表：users 10 行、fiat_transactions 25 行、crypto_transactions 25 行、exchange_rates 8 行。原生 DuckDB 测试从该 XLSX 读取原始字段类型和值，独立计算预期结果，不用模拟业务结果。

- 法币：completed + USD，9 行、13 个对象、9 条关系。
- 加密资产：completed + USDT，15 行、22 个对象、15 条关系。
- 两类交易的 uid 均有重复，不能作为交易唯一标识；订单号可通过唯一性检查，用户 uid 可通过用户表检查。
- 筛选值包含引号或 SQL 片段时按字面值匹配，不能扩展查询范围。
- 汇率表仍支持高级复合映射，不把基准汇率日期解释为交易当日汇率。

浏览器使用当前真实持久库 `sql_funds_flow`。该库与原始 XLSX 的部分描述属性不同；浏览器结果与工作簿原生测试分别验证，不声称两份数据完全相同。

目标回归 7 个文件、76 项检查通过（主回归 72 项及图谱数据检查 4 项）；当前代码 TypeScript 检查通过，最终生产构建通过（49.71 秒）。现有依赖 eval、混合导入和包体积提示仍在。第一次并行构建期间出现测试线程启动超时，随后完成串行复验；该超时不作为产品缺陷。未运行整个仓库测试集。

## 后续优先级（尚未实现）

| 优先级 | 下一步 | 验收边界 |
|---|---|---|
| P1 | 复合对象标识和多关联的可视化配置 | 汇率等复合键无需 JSON；仍需保留真实字段及关联语义 |
| P1 | 按字段类型提供日期范围、数值区间 | 避免以文本顺序处理数值和时间；时区和空值语义明确 |
| P2 | 保存可复用的任务筛选 | 绑定数据库及结构版本；上下文变化要求重新校验，不跨库沿用旧映射 |
| P2 | 大表身份检查与字段值建议的性能优化 | 当前唯一性检查会扫描真实表；需用大型真实数据测量后优化，不能用抽样冒充唯一性证明 |

## 验收限制

同名字段只是候选，唯一性检查不能证明业务关联含义；仍需用户确认。引导筛选目前是区分大小写的文本等于、不等于、包含和 NULL 判断，数值区间及日期范围使用高级 SQL。建议列表最多 50 个值，仍允许输入其他值。截图不能证明屏幕阅读器与全部键盘路径无障碍；本轮保留语义表单、标签、禁用态和焦点样式，未宣称完整无障碍认证。未发布、未提交远程。
