# 首页看板稳定性治理与维护

日期：2026-10-14。修改在现有工作区上增量实施；没有提交、推送或触发远端发布。原工作区已有大量其他未提交工作，本次基线保存在 `before/`，只代表开始时的局部文件状态。

## 已落实的契约

1. **卡片故障隔离**：每个 DashboardWidget（含其全屏 portal）使用独立 WidgetErrorBoundary。渲染异常仅替换当前卡片，可重试；其他实例保持挂载。查询失败仍使用原有查询错误和重试流程。
2. **布局只由保存定义与容器宽度决定**：桌面沿用 12 列保存坐标；容器不足 960px 时按保存的 y/x 顺序单列阅读，高度仍由保存的 h 决定。不再用查询结果的行数、类型或回调修改整板布局。编辑画布的最小宽度同为 960px；窄屏编辑允许画布内部横向滚动。视口转换不保存坐标。
3. **配置校验与隔离**：读取和写入检查版本、组件列表、引用、重复实例、整数几何、画布范围及基本筛选/刷新配置。读取逐条隔离非法 JSON、未知未来版本及非法看板记录，显示错误提示、保留原记录；不以空看板覆盖损坏的默认/当前视图。仍能选择其他有效视图。合法旧版本只在内存补默认值，保留身份、SQL 引用与几何。
4. **只读数据源的可写配置归属**：可写数据库继续使用原 `__studio.objects`。只读数据库的分析、视图和配置使用独立 IndexedDB `DuckDBStudioReadonlyConfiguration`，以 `[catalog, kind, id]` 隔离；源库已有配置只读载入，浏览器修改覆盖同身份记录，删除使用 tombstone 防止源记录重新出现。事务提交完成才报告保存成功，失败向上抛出。页面明确说明配置保存在此浏览器，源文件保持只读。
5. **异步生命周期**：Widget 复用既有 useVisualizationRequest 代次门控；新请求和卸载失效旧响应。保留当前数据库检查和原结果作用域检查。看板写入继续对同视图串行、基于最新成功保存合并；发布结果额外检查挂载、数据库、视图；布局保存中禁用完成编辑，失败不伪报成功。
6. **诊断**：会话内保留最近 50 条结构化异常，记录阶段、数据库/视图/实例身份、版本和错误代码，不记录 SQL、数据行、参数或堆栈。有异常时可在看板导出诊断 JSON；此功能不上传日志。会话刷新后诊断记录不保留。
7. **发布门槛**：部署工作流调用同一质量检查工作流，等待类型检查、全部单元/集成测试、真实数据浏览器检查和构建成功后，下载并部署该轮验证过的构建产物。失败时上传浏览器证据；不会在部署任务中另建未经检查的包。

## 日常维护

```powershell
pnpm typecheck
pnpm test:run
pnpm exec playwright install chromium
pnpm test:dashboard:browser
pnpm build
```

浏览器脚本默认启动独立的 5186 端口，使用独立浏览器上下文，结束后关闭自己启动的服务。也可设置 `DASHBOARD_BASE_URL` 使用已启动的本地开发服务。运行中冻结产品代码，避免热更新让版本混用；不要将并行编辑期间的失败/通过日志当成最终验收。

维护时遵循以下顺序：

1. 保留故障看板的原配置，记录数据库、视图、组件、触发步骤、诊断 JSON 与截图。先区分查询失败、渲染异常、布局错误和保存失败。
2. 以原输入建立失败断言；对单卡、布局或存储做最小修改，关联检查空/错结果、加载中、重试及切换作用域。
3. 布局改动必须验证保存坐标不被视口/数据刷新写回；写入改动必须验证提交失败、并发、重载和数据库隔离。
4. 新增配置字段要定义默认值、版本迁移和未来版本拒绝行为，不可静默覆盖旧记录。
5. CI 未通过不得发布；发布使用检查产物。浏览器 trace 和 JSON 是失败定位入口，不以构建成功或截图看起来正常替代行为断言。

## 边界

- 不自动重排并覆盖用户保存的旧布局；桌面极小卡片可能仍需要内部滚动或全屏查看。
- 只读源配置保存在当前浏览器的 IndexedDB，未写回源 DuckDB，也不会随仅导出源数据库文件跨设备迁移；清除站点存储会清除该配置。
- 本轮没有建立所有慢 SQL、高组件数、长标签、极端数据量及全部计算语义的压力验收，也没有把原有全部业务入口视为浏览器验收通过。
- 真实浏览器门禁的主体是生产 HomeBoardCanvas/Grid/Widget 与真实引擎的独立验收页；正式应用入口的覆盖单独列明。
- 远端 CI 与部署只修改规则，未在本轮触发。全局未提交修改仍保留，本次没有合并、回滚或提交其他任务的工作。
- **当前发布阻断：生产依赖审计。** `dependency-audit.json` 检出 8 项（3 low / 5 moderate，0 high / critical），涉及既有 Mermaid、DOMPurify、KaTeX；这几项版本在开始时的锁文件中已存在。本轮添加的 Playwright 是开发依赖。现有审计步骤保持阻断，不将其删除或降级为提示，因此不能宣称当前整套远端质量门槛已通过。相关依赖修补需要另外验证图形与 Markdown 渲染兼容性。
