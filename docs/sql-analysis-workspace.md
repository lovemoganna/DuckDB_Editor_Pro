# SQL 驱动的分析工作台

## 使用方式

1. 在首页「上传 / 更新 SQL」选择一个 DuckDB 兼容的数据库 SQL 文件。无需配置 AI 或数据源。系统在支持 OPFS 的环境中自动创建持久数据库，保存原始 SQL，并读取实际结构、字段、类型和关联。
2. 系统基于实际数据生成探索指标、图表和数据概况。进入「指标」可以修改口径；进入「可视化」可以调整呈现；进入「分析」可以重新计算并保存笔记。
3. 首页选择「添加分析内容」，引用指标、可视化或分析。同一个对象可重复加入，组件实例拥有独立位置与尺寸，定义与数据共用。
4. 输入视图名称创建独立工作台。解锁布局后拖动组件标题栏，或拖动边缘改变尺寸。调整会自动保存；完成后选择「保存并锁定布局」。组件菜单可移除当前实例、进入关联分析、打开 SQL 或追溯来源表。
5. 上传修改后的同名 SQL，自动重建该来源声明的表并刷新下游，保留编排、修改过的指标和分析笔记。导入失败会回滚数据库。也可使用「从保存的 SQL 重载」重现基准、「下载 SQL 副本」备份原始输入。

## 数据与对象关系

SQL 来源 → 数据库 → 共享数据模型 → 原始指标 → 原始可视化 / 分析 → 首页对象引用 → 独立组件实例与布局。

首页不维护第二份指标 SQL。依赖字段被改名、指标或图表被删除时，组件显示具体失效原因，不能继续展示旧结果。删除自动生成的指标、图表、分析或指标包会保存删除选择，刷新不会悄悄恢复。修改原始对象会影响所有引用它的组件。

分析定义、对象引用、布局和笔记保存在当前数据库的应用元数据中；原始 SQL 另外存入浏览器本地存储。重新打开页面会恢复上次 SQL 工作区。不同数据库隔离数据、对象和编排。

## 计算范围

- 自动发现以当前数据库、当前 Schema 为分析范围；现有数据库 / Schema 选择器可切换分析范围。当前实现没有对任意 SQL 文件的所有 Schema 做一次全库联合发现。
- 自动指标是探索起点，不能自动推断所有业务规则。交易金额统计明确包含全部状态；完成交易、净流量、汇率换算等应使用明确的 SQL 口径。
- 不同货币或资产分组显示，避免混合单位直接求和。编号、等级、价格、汇率不自动生成求和指标。
- 关系会区分声明外键与字段名推断，推断不能替代真实约束。
- 外部磁盘文件改变后，需要重新选择更新的 SQL；浏览器不会持续监听原始文件。数据库内的数据变更及加载更新 SQL 后，下游自动重算。
- SQL 必须能在 DuckDB 中执行。事务由导入流程管理；数据库切换、外部导入 / 导出等脚本指令会给出明确错误。OPFS 不可用时会显示内存模式与持久化限制。

## 本次验证

使用四张真实练习表导出的 SQL：users 10 行、fiat_transactions 25 行、crypto_transactions 25 行、exchange_rates 8 行，共 68 行、38 个字段。识别 16 个可复用探索指标，并生成关联图表和分析。

已验证：多视图、重复引用、单实例移除、真实拖拽、调整尺寸、保存锁定、页面重载恢复、指标定义同步、笔记同步、同名 SQL 重载、金额变化自动刷新、失败导入回滚、字段改名失效提示。测试修改已恢复，原始本地 DuckDB 基准文件未改变。

证据保存在 `artifacts/dynamic-workspace/`：SQL 输入、架构巡检记录、界面截图、操作快照、类型检查、回归测试与构建日志。
